Overview

Before & after

This project involved redesigning a payment item creation flow that had accumulated complexity over time. The original flow had grown difficult to navigate — too many fields visible simultaneously, inconsistent field grouping, and unclear step progression for administrators setting up payments.

The redesign produced a cleaner stepped layout, better separation of user-facing and internal information, and improved labelling throughout. Both versions exist as functional HTML prototypes — shown below for direct comparison.

The Problem

Complexity without clarity

The original form presented all configuration options on a single long page — payment type, pricing, order limits, variants, recipient settings, consent options, and a review step — with no clear visual hierarchy between steps and no distinction between what administrators configure internally versus what users see.
